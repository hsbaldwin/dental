# W치과 웹 솔루션

환자용 홈페이지, 온라인 예약, 직원용 관리 화면이 하나로 묶인 치과 웹 서비스입니다.
Node.js만 있으면 설치할 패키지 없이 실행되고, 데이터는 SQLite 파일 하나에 저장됩니다.

- 홈페이지 시안과 W치과 경쟁 사이트 조사는 [`docs/research.md`](docs/research.md)에 있습니다.
- 서버 없이 눌러보는 체험판은 `npm run build:demo`로 `dist/demo/`에 만들 수 있습니다.

## 할 수 있는 일

| 누가 | 기능 |
|---|---|
| 환자 | 증상으로 진료 찾기 · 남은 자리를 보고 날짜/시간 예약 · 예약번호로 조회·취소 · 진료시간/휴진일/비급여 진료비/공지 확인 |
| 직원 | 센터 데스크(상담 요청 처리, 센터별 접수 상태·대기·담당자·인사말) · 대시보드(오늘 일정, 확인 대기, 7일 예약, 미내원율, 홈페이지 실시간 안내 입력) · 예약 확정/변경/취소/내원/미내원 처리 · 전화 예약 직접 등록 · 검색과 엑셀(CSV) 내려받기 · 새 예약 30초 자동 확인 |
| 관리자 | 진료센터 내용 · 진료시간·점심시간·휴진일 · 예약 규칙(예약 단위, 시간대당 인원, 예약 가능 기간 등) · 병원 정보 · 비급여 진료비 · 의료진 · 공지 · 직원 계정 · 활동 기록 |
| 자동 | 예약 접수/확정/변경/취소 문자 · 전날 오전 10시 이후 내원 안내 문자 · 새 예약 직원 알림 · 보관 기간이 지난 개인정보 자동 파기 |

관리 화면에서 바꾼 내용은 저장하는 즉시 홈페이지에 반영됩니다. 홈페이지를 다시 만들 필요가 없습니다.

### 홈페이지 흐름: 5단계 고객 여정

| 단계 | 담긴 단락 | 끝에서 이어지는 곳 |
|---|---|---|
| 1 지금 | 큰 버튼 4개, 어르신 건강보험 안내, 안내 챗봇 | (챗봇·큰 버튼이 바로 예약·센터로) |
| 2 찾기 | 진료센터 접수 데스크 카드 | → 3 알아보기 |
| 3 알아보기 | 진료 원칙, 첫 방문 과정·치료계획서, 의료진, 진료비 | → 4 예약 |
| 4 예약 | 실시간 예약, 내 예약 진행 상황, 예약 확인·채널 | → 5 오시는 날 |
| 5 오시는 날 | 오늘 진료 시간표·병원 안내·오늘 의료진·휴진, 진료시간·오시는 길, 공지 | 챗봇에게 묻기 · 처음으로 |

- 한 단계는 한 배경 덩어리이고, 단계 안 단락은 가는 선으로만 나눕니다. 단계 첫 단락 소제목에 번호, 끝마다 '다음 단계' 연결.
- 넓은 화면(1440px 이상)에서는 왼쪽에 여정 표시가 고정되어 지금 단계를 알려줍니다. 크게 보기·휴대폰에서는 숨깁니다.
- 헤더는 1360px 이하에서 진료센터 메뉴를 '메뉴' 버튼으로 접어 어느 너비에서도 넘치지 않습니다.

### 디자인 시스템: 건강한 입속의 색과 모양

`design/` 폴더가 화면 규칙의 원본입니다. 색·글자·간격을 바꿀 때는 `design/tokens.json`을 먼저 고치고 `public/css/site.css` 맨 위 `:root` 값을 맞춥니다.

| 파일 | 내용 |
|---|---|
| `design/brand-book.md` | 말투(존댓말, 오후 2:30, 진단 금지), 색 쓰임표, 글자, 치관 모서리, 실시간 표식, 크게 보기, 아이콘 규칙 |
| `design/tokens.json` | 색 19개(밝은·어두운 화면, 모든 글자 색 4.5:1 이상 확인), 글자 9단계, 간격, 모서리, 그림자, 누르는 크기 |
| `design/components.css` | 컴포넌트 12종 참고 구현 (`wd-` 클래스) |
| `design/w-mark.svg` | 어금니 교두 W 로고 |

- 색의 뜻: **법랑질 화이트** 바탕 · **틸** 주요 행동 · **민트** 실시간·상쾌함(장식 면, `mint-soft` 상자) · **잇몸 핑크** 돌봄 안내(한 화면 한 곳) · **상아색(VITA A2)** 치료계획서 같은 진료 기록 · **주의 갈색** 점심·중단
- 모양: 카드와 대화창은 **치관 모서리**(위 22px, 아래 12px). 셰이드 탭은 치아 모양.
- **진료센터 길 안내 색**: 임플란트 틸 · 교정 파랑 · 충치·신경 앰버 · 심미 장미 · 잇몸 초록 · 소아 주황 · 턱관절 보라. 센터 카드 머리 띠, 메뉴, 센터 데스크 영역, 쉬운 예약 선택지에 같은 색. 진한 색(`-solid`) 위에는 글자를 올리지 않음.
- **상쾌함과 색의 리듬**: 1 지금과 바닥글은 맑은 민트(`fresh`)에 흰 거품 원(`foam`), 공지 띠는 맑은 틸, 2 찾기 흰 면, 3 알아보기 바탕색, 4 예약 옅은 틸, 5 오시는 날 바탕색. 짙은 바탕 면은 쓰지 않습니다. 물빛 아쿠아(`aqua`)는 다음 단계 카드·단계 번호 둘레 같은 장식에만.
- **세라믹 면**: 헤더 W 로고 칩, 첫 화면 흰 큰 버튼, 진료센터 카드, 챗봇 창, 셰이드 탭에만 지르코니아 같은 유약 한 겹(위 빛줄, 2~3% 결, 왼쪽 위 은은한 광, 아래 얇은 그늘). 표·입력칸·본문 바탕에는 쓰지 않고, 크게 보기에서는 평평하게.
- **민트 숨결**(`public/js/breeze.js`): 화면이 향을 낼 수는 없어서, 첫 화면 뒤로 반투명 민트 잎과 기포가 아주 천천히 떠올라 갓 양치한 뒤의 시원한 숨결을 눈으로 느끼게 합니다. 화면 밖·탭 숨김·움직임 줄이기·크게 보기에서는 멈춥니다. 대기실 민트 디퓨저와 함께 쓰면 온라인과 병원의 첫인상이 이어집니다.

### 어르신도 쉽게 (60대 후반 이용객 기준)

모든 이용객에게 기본으로 적용:
- 본문 글씨 17px, 회색 글씨의 대비를 높이고, 버튼은 손가락으로 누르기 쉬운 44px 이상
- 시각은 `14:30` 대신 **오후 2:30**, 문자 메시지는 **오후 2시 30분**처럼 표기 (`core.koTime`)
- 영어·전문용어 제거: LIVE → 실시간, Reception → 접수 데스크, 타임 → 자리, 진료X → 진료 없음
- 첫 화면 맨 위에 큰 버튼 4개: **전화하기**(번호를 크게, 지금 통화 가능 여부) · **진료 예약하기**(가장 빠른 시간) · **오늘 진료하나요?** · **오시는 길**
- "만 65세 이상이신가요?" 임플란트·틀니 건강보험 안내 띠
- 헤더에 대표 전화번호, 챗봇 메뉴에 '전화번호 알려줘요', 알림 메시지는 8초 동안 표시

**크게 보기(쉬운 화면)** — 헤더의 '가 크게 보기' 버튼, 처음 방문하면 "글씨가 작게 보이시나요?"라고 한 번 물어봄. 선택은 그 기기에 기억됩니다.
- 글씨·버튼 1.25배, 움직이는 효과 끄기
- 복잡한 요소 숨김: 7일 예약 현황표, 진료 타임라인, 상단 메뉴 7개(대신 '메뉴' 버튼), 실시간 띠의 부가 정보
- 예약 날짜는 옆으로 밀지 않고 여러 줄로, 시간 버튼과 데스크 메뉴는 크게 2열로

### 쉬운 예약 (어르신용 단계별 안내)

첫 화면의 큰 '진료 예약하기 · 쉬운 예약' 버튼, 휴대폰 하단 '예약하기', 크게 보기 상태의 센터 데스크 '진료 예약'에서 열립니다(`public/js/easybook.js`).

- 한 화면에 질문 하나: 진료 → 날짜 → 때(오전·오후·저녁) → 시간 → 성함 → 전화번호 → 확인 (7단계, "3 / 7 단계" 글자 표시)
- 잘 모르면 맨 위 '검진 · 상담'. 고를 수 없는 날·때도 숨기지 않고 "자리 없음"으로 보여줌
- 전화번호는 큰 숫자판(010 미리 입력, 하이픈 자동), 확인 화면은 줄마다 '고치기'
- 언제나 '← 이전'과 '전화로 할게요'(대표번호 크게 + 전화 걸기)
- 디자인 시스템의 어르신 컴포넌트(StepProgress, BigChoice, NumberPad, ConfirmSummary, WizardFooter)와 같은 규칙

### 간결하게: 한 화면에 한 질문

어르신께 글자가 많아 보이지 않도록 휴대폰(390px) 기준으로 재며 줄였습니다.

| | 줄이기 전 | 지금 |
|---|---|---|
| 홈 첫 화면 글자 | 약 330자 | 약 170자 (크게 보기 약 150자) |
| 홈 전체 글자 | 약 3,700자 | 약 1,260자 |
| 홈 길이 | 화면 18장 | 화면 8장 |
| 센터 데스크 전체 글자 | 약 2,090자 | 약 1,480자 |

- **첫 화면**: "무엇을 도와드릴까요?" 한 질문과 챗봇 큰 버튼 다섯(예약하기 · 아픈 곳이 있어요 · 오늘 진료하나요? · 전화로 할게요 · 다른 것 물어보기). 나머지 질문은 '다른 것 물어보기' 안에. 첫 화면이 보이는 동안 아래 버튼 줄은 숨김(같은 버튼이 챗봇에 있음).
- **휴대폰 상단**: 공지 띠 대신 실시간 줄에 '공지' 표시, 실시간 줄은 진료 상태만. 크게 보기 권유는 한 줄 + 버튼 둘.
- **펼쳐 보기**: 진료 원칙 · 첫 방문 · 의료진 · 진료비 · 오늘의 병원 · 진료시간과 오시는 길, 센터 페이지의 진료 과정 · 의료진 · 비용 · 자주 묻는 질문은 제목과 한 줄만 보이고 '자세히 보기'로 펼침. 메뉴나 링크로 가면 저절로 펼쳐짐.
- **예약(휴대폰 · 크게 보기)**: '쉬운 예약 시작'을 먼저, 한 화면 예약 폼은 '한 화면에서 예약하기'로 펼침. 다른 곳에서 날짜 · 시간을 골라 들어오면 폼이 펼쳐진 채로.
- **같은 말 줄이기**: 센터 데스크의 반복 제목 · 영문 머리말 · 경로 표시 숨김, 데스크 메뉴 설명은 예약 · 전화 상담만, 센터 카드는 이름 · 접수 상태 · 가장 빠른 예약 세 줄.
- 확인 방법: 사용성 테스트 진행표의 **5초 테스트**.

### 그림 안내 (글자는 그대로, 그림을 곁에)

글자를 그림으로 바꾸지 않고 **글자 옆에 그림을 붙입니다**. 음성 안내 · 크게 보기 · 화면 읽기 프로그램은 계속 글자를 씁니다.

- **증상 그림 8개**(이가 시려요 · 씹을 때 아파요 · 잇몸 피 · 이가 빠졌어요 · 치아가 삐뚤어요 · 턱 소리 · 아이 첫 검진 · 치아 색): 예약 화면 증상 타일, 챗봇 빠른 답변, 쉬운 예약의 '어디가 불편한지 그림으로 고르기'에 같은 그림.
- **아픈 곳 짚기**: 거울을 볼 때처럼(화면 오른쪽 = 내 오른쪽) 윗니 · 아랫니 × 왼쪽 어금니 · 앞니 · 오른쪽 어금니 6곳 중 여러 곳을 누름. 고른 곳은 예약 메모에 "아픈 곳: 윗니 오른쪽 어금니"처럼 들어가 원장님이 미리 봅니다. 시림 · 씹을 때 통증 · 잇몸 · 빠진 이 · 치아 색 증상에서만 나오고, 늘 건너뛸 수 있습니다.
- **비교 시험**: 주소 끝에 `?picto=0`이면 그림 없이 글자만(그 탭에서 유지), `?picto=1`로 되돌림.
- **어르신 사용성 테스트 진행표**: [`docs/usability-test-seniors.md`](docs/usability-test-seniors.md) — 참여자 기준, 진행 대본, 과제 6개, 기록지, 끝난 뒤 질문, 동의서, 결과 판단 규칙.

### 음성 안내

브라우저에 들어 있는 음성 기능을 씁니다(`public/js/voice.js`, 서버·비용 없음).

- **소리로 듣기**(헤더): 켜면 지금 병원 상황(진료 중 여부, 가장 빠른 예약, 전화번호)을 읽고, 이후 쉬운 예약의 질문·선택지·오류, 챗봇의 답, 예약 완료 안내를 읽습니다. 처음 방문 안내에서 "소리로도 들을래요"로 켤 수 있고, 그 기기에 기억합니다.
- **다시 듣기**(쉬운 예약 맨 위): 소리를 꺼 두었어도 지금 화면을 한 번 읽습니다.
- **말하기**(챗봇 입력칸 옆): 지원 브라우저(크롬·엣지·사파리 등)에서만 보이며 "이가 시려요"처럼 말로 묻습니다. 브라우저의 음성 인식은 브라우저 회사의 서버로 음성을 보낼 수 있으니 개인정보처리방침에 적어 두세요.
- 읽는 말 변환(`speakable`): "오후 2:30" → "오후 2시 30분", "010-1234-5678" → "공일공, 일이삼사, 오육칠팔", 예약번호 한 글자씩, "(수)" → "수요일", "3 / 7 단계" → "7단계 중 3단계". 속도 0.9배, 한국어 목소리가 있으면 그 목소리로.
- 한국어 목소리가 기기에 없으면 기본 목소리로 읽습니다(대부분의 휴대폰·윈도우·맥에는 한국어 목소리가 있습니다).

### 첫 만남: 안내 챗봇

홈페이지 첫 화면은 안내 챗봇입니다. 다른 화면에서는 오른쪽 아래 '챗봇 상담' 버튼(휴대폰은 하단 바)으로 같은 대화를 이어갑니다.

- 인사부터 실시간: "진료 중 · 18:30까지 · 가장 빠른 예약 오늘 12:00", 병원 안내 문구, 이 기기의 기존 예약 상태
- 대화로 끝까지: 증상 → 맞는 진료센터와 데스크 현황 → 남은 시간 6개 → 성함 · 연락처 → 동의 → 예약 신청 (예약 화면과 같은 API)
- 상담원과 통화: 센터 · 연락 희망 시간 · 성함 · 연락처 → 센터 데스크 상담 요청함으로 접수
- 그 밖에: 오늘 진료하는 센터, 센터별 비급여 비용, 내 예약·상담 요청 조회, 오시는 길
- 직원이 예약을 확정하거나 상담 요청을 확인하면 챗봇이 대화로 바로 알려줍니다.
- 자유 입력은 단어 인식으로 의도를 고릅니다(`public/js/core.js`의 `SYMPTOMS`, `INTENTS`). 이해하지 못하면 메뉴와 상담원 연결을 제안합니다.
- **규칙 기반이라 진단·치료 효과를 말하지 않습니다.** 심한 출혈·붓기·외상 같은 말에는 바로 전화나 응급실 이용을 안내합니다. 생성형 AI를 붙이려면 의료광고·개인정보 기준을 먼저 정하고 답변 범위를 제한하는 것을 권합니다.

### 메뉴 구조: 진료센터가 1 depth

| depth | 구성 |
|---|---|
| 1 depth (상단 메뉴 · 첫 화면) | 임플란트 · 교정 · 충치·신경치료 · 심미·미백 · 잇몸 · 소아치과 · 턱관절 센터. 메뉴 옆 점(●)은 오늘 진료 여부, 첫 화면 카드는 오늘 진료 원장과 센터별 가장 빠른 예약 시간을 실시간으로 표시. '잘 모르겠어요' 카드는 증상 선택 → 검진·상담 예약 |
| 2 depth (센터 페이지 `#center-<key>`) | 센터 소개 · 진료 과정 · 의료진 · 비용 · 자주 묻는 질문 · 예약. 상단 '센터 실시간 현황'(오늘 진료, 진료 요일, 오늘 진료 원장, 가장 빠른 예약, 7일 예약 현황) |
| 병원 안내 (보조 메뉴) | 오늘의 병원 · 의료진 · 진료비 · 진료시간·오시는 길 · 공지 |

센터 예약은 **그 센터 담당 원장님의 진료 요일에만** 열립니다(관리 화면 → 의료진 → 담당 진료센터 · 진료 요일). 원장님 담당이나 요일을 바꾸면 홈페이지의 센터 카드, 센터 페이지, 예약 가능한 날짜가 즉시 바뀝니다. 센터 소개·진료 과정·자주 묻는 질문은 관리 화면 → 진료센터에서 고칩니다. 처음 설치할 때 들어가는 기본 내용은 `public/js/seed.js`에 있습니다.

### 센터별 프론트 데스크

센터 페이지는 그 센터의 접수 데스크처럼 동작합니다.

| 환자 화면 | 직원 화면 (관리 → 센터 데스크) |
|---|---|
| 데스크 인사말과 담당 코디네이터, '데스크 현황'(접수 중 · 점심 · 오늘 진료 없음 · 온라인 접수 잠시 중단, 현재 대기, 상담 요청 대기 건수) | 센터마다 온라인 상담 요청 받기 켜고 끄기, 현재 대기(3시간 뒤 자동 해제), 담당 코디네이터, 데스크 인사말 |
| "무엇을 도와드릴까요?" 창구 메뉴: 진료 예약 · 전화 상담 요청 · 내 예약·요청 확인 · 첫 방문 준비물(체크리스트) · 비용 안내 · 오시는 길·주차 | 상담 요청함: 오래된 순, '확인했어요' → '연락 완료', 통화 메모, 새 요청 알림과 메뉴 배지 |
| 전화 상담 요청 후 '접수 → 데스크 확인 → 연락 완료' 진행 표시와 앞선 요청 수. 직원이 처리하면 새로고침 없이 바뀜 | 대시보드 '상담 요청 대기' 지표 |

인사말을 비워두면 접수 상태에 맞는 기본 인사말(점심시간, 진료 없는 날, 접수 전 등)이 자동으로 나갑니다. 첫 방문 준비물은 관리 → 진료센터에서 고칩니다. 상담 요청도 예약과 같은 보관 기간이 지나면 성함·연락처가 자동 파기됩니다.

#### 접수 카운터 배경 — 실제 운영 정보로 현실감 내기

센터 데스크 화면 아래에는 그 센터의 접수 카운터가 그려져 있고, 카운터 위 소품은 **모두 지금의 운영 정보 그대로**입니다(꾸민 그림이 아님).

| 소품 | 보이는 것 | 연결 |
|---|---|---|
| 상태등 | 접수 중 초록 불 · 점심/온라인 중단 호박색 · 접수 전/마감/휴진 꺼짐 | 진료시간표 · 휴진일 · 온라인 접수 켜고 끄기 |
| 대기 표시기 | 대기 약 10분 / 상담 요청 N건 / 바로 안내 (접수 중일 때만) | 센터 데스크 현재 대기 · 상담 요청함 |
| 담당 명패 | 오늘 접수 · 이○○ 실장 | 센터 데스크 담당 코디네이터 |
| 탁상시계 | 오전 10:40 (병원 서버 시각) | 서버 시계 |
| 안내 팻말 | 점심시간 · 잠시 자리 비움 / 오늘은 이 센터 휴진 / 온라인 접수 잠시 중단 | 접수 상태 |

- **시간대 조명**: 오전 맑은 민트빛 → 오후 살짝 따뜻하게 → 저녁 노을빛 → 접수 마감 · 휴진이면 카운터 조명만 은은하게. 천장 조명 두 개가 상판 위에 빛 웅덩이를 만듭니다.
- **재질**: 세라믹 상판의 그림자, 앞판 무광 결(아주 옅은 노이즈), 바닥 쪽 걸레받이 그림자.
- **실제 사진**: 관리 → 센터 데스크 → '접수 데스크 사진'에 `/img/desk/<센터키>.webp`를 넣으면 그림 뒤에 흐리게 깔립니다. 촬영 규칙은 [`docs/desk-photo-guide.md`](docs/desk-photo-guide.md).
- 글자 대비는 그대로(모두 배경 층), 누르는 것을 막지 않음, 화면 읽기 프로그램은 읽지 않음(같은 정보가 '데스크 현황'에 있음). 휴대폰·태블릿처럼 한 줄로 쌓이는 화면에서는 현황판이 카운터 위 모니터 역할을 하므로 소품은 숨깁니다. '크게 보기'에서는 더 옅게, 상태등 깜빡임도 멈춥니다.

### 환자가 '병원과 실시간으로 연결되어 있다'고 느끼게 하는 화면 구성

| 위치 | 보이는 것 | 연결된 업무 |
|---|---|---|
| 헤더 아래 실시간 띠 | 실시간 연결 상태 · 진료 중/점심/종료 · 현재 대기 · 오늘 남은 예약 · 가장 빠른 예약 · 갱신 시각 | 진료시간표, 예약 장부, 직원이 대시보드에서 입력한 대기 시간 |
| 첫 화면 '실시간 예약 현황' | 가장 빠른 예약 시간(바로 예약 버튼), 7일 × 오전/오후/저녁 남은 자리 | 예약 장부 · 휴진일. 다른 환자가 예약하면 즉시 줄어듦 |
| 오늘의 W치과 | 오늘 진료 타임라인(지금 위치, 점심, 남은 시간), 병원 안내 문구, 오늘 진료 의료진, 다가오는 휴진 | 진료시간 · 의료진 진료 요일 · 휴진일 · 직원 안내 |
| 예약 폼 | 날짜별 남은 타임, 시간 버튼 실시간 마감 표시, 선택한 시간이 다른 사람에게 먼저 잡히면 알림 | 예약 장부 |
| 내 예약 진행 상황 | 신청 접수 → 병원 확인 → 예약 확정 → 내원 단계 표시. 직원이 확정하면 새로고침 없이 바뀌고 알림 | 직원의 예약 처리 |
| 의료진 | '오늘 진료' 표시 | 의료진 진료 요일 |

서버는 예약·설정이 바뀔 때 열려 있는 홈페이지에 신호를 보냅니다(Server-Sent Events, `/api/live/stream`). 신호에는 개인정보가 없고, 브라우저는 신호를 받으면 `/api/live`를 다시 읽습니다. 연결이 안 되는 환경에서는 20초마다 다시 읽습니다. Nginx 뒤에서 운영한다면 해당 경로의 `proxy_buffering`을 끄세요(서버가 `X-Accel-Buffering: no`를 보냅니다).

## 로컬 테스트 (가장 쉬운 방법)

Node.js 22.13 이상만 있으면 됩니다. 설치할 패키지도 `.env`도 필요 없습니다.

```bash
npm run local
```

- 홈페이지 http://localhost:3000 · 관리 화면 http://localhost:3000/admin/ (아이디 `admin` / 비밀번호 `local1234`)
- 처음 실행하면 **예시 데이터**가 들어갑니다: 오늘부터 7일 치 예약(확인 대기 · 확정 · 오늘 지난 시간은 내원 · 미내원), 센터 데스크 담당자 · 대기 시간 · 인사말, 전화 상담 요청 3건, 홈페이지 실시간 안내.
- 데이터는 `data/local.db`에 따로 저장되어 실제 운영 데이터(`data/wdental.db`)를 건드리지 않습니다. 문자 · 알림은 실제로 보내지 않고 관리 → 발송 기록에만 남습니다.
- 같은 와이파이의 휴대폰으로 볼 수 있는 주소도 함께 출력됩니다(어르신 화면 · 음성 안내 확인용).

**시간 이동**: 점심시간 · 저녁 · 휴진일 화면을 기다리지 않고 바로 확인합니다. 정한 시각부터 시계가 실제처럼 흘러갑니다.

```bash
npm run local -- lunch
```

| 이름 | 상황 |
|---|---|
| `open` | 평일 오전 10:40 · 접수 중 |
| `lunch` | 평일 오후 1:20 · 점심시간 |
| `evening` | 평일 오후 5:50 · 마감 40분 전 |
| `night` | 화요일 오후 7:30 · 야간 진료 |
| `closed` | 평일 오후 7:30 · 진료 종료 후 |
| `before` | 평일 오전 8:50 · 진료 시작 전 |
| `saturday` | 토요일 오전 11:00 |
| `sunday` | 일요일 · 휴진 |

원하는 시각은 `npm run local -- --at "2026-11-10 19:30"` 또는 `--at "13:10"`(오늘).

| 명령 | 하는 일 |
|---|---|
| `npm run local:reset` | 로컬 데이터를 지우고 예시 데이터로 새로 시작 (시간 이동과 함께 쓰면 그 날짜 기준으로 예약이 채워짐) |
| `npm run local:watch` | 코드를 고치면 서버가 저절로 다시 켜짐 (화면은 새로고침) |
| `npm run local -- --empty` | 예시 데이터 없이 빈 상태로 (`--reset`과 함께) |
| `npm run local -- --port 3001` | 다른 포트로 |
| `npm run check` | 자동 테스트 + 체험판 빌드까지 한 번에 (올리기 전 확인용) |
| `npm run local -- --help` | 도움말 |

관리 화면의 '오늘'도 서버 시각을 따르므로, 시간 이동 중에는 대시보드 · 예약 관리도 그 날짜 기준으로 보입니다.


## 문자 · 알림 연동

모든 발송은 관리 화면 **기록 → 문자 · 알림 발송**에 남습니다. 연동 전에는 '미발송 (연동 전)'으로 기록만 됩니다.

| 설정 | 보내는 내용 | 형식 |
|---|---|---|
| `NOTIFY_WEBHOOK_URL` | 직원 알림 (새 예약, 환자 취소) | `POST {"text": "..."}` — Slack·잔디·카카오워크 수신 웹훅에 바로 연결 |
| `SMS_WEBHOOK_URL` | 환자 문자 (접수, 확정, 변경, 취소, 전날 안내) | `POST {"to": "01012345678", "text": "..."}` |

문자 발송 업체(솔라피, 알리고, NHN Cloud 등)는 API 모양이 서로 다릅니다. 그래서 위 형식을 받아 업체 API로 넘겨주는 작은 중계(Make·Zapier 같은 자동화 도구나 서버리스 함수)를 두는 방식으로 열어 두었습니다. 카카오 알림톡은 발신 프로필과 템플릿 심사가 필요하므로 업체와 계약한 뒤 같은 방식으로 연결합니다.

## 백업

```bash
npm run backup
```

`backups/wdental-날짜.db` 사본이 생깁니다. 서버가 돌아가는 중에도 안전합니다. 매일 실행되도록 예약 작업(cron)에 넣고, 사본은 다른 장소에도 보관하세요. Docker에서는 `docker exec w-dental node --disable-warning=ExperimentalWarning scripts/backup.js`로 실행합니다(사본은 `/data` 볼륨이 아니라 컨테이너 안에 생기므로 `BACKUP_DIR=/data/backups`를 함께 지정하세요).

## 보안 · 개인정보

- 비밀번호는 scrypt로 해시하고, 로그인은 HttpOnly·SameSite=Strict 쿠키(12시간)로 유지합니다.
- 관리 API의 변경 요청은 전용 헤더와 같은 출처일 때만 받습니다(CSRF 방지).
- 로그인 시도, 예약 신청, 예약 조회에 IP별 횟수 제한이 있습니다. 예약 폼에는 스팸 방지용 숨김 필드가 있습니다.
- 모든 응답에 CSP 등 보안 헤더를 붙입니다. 화면은 외부 스크립트를 쓰지 않습니다(글꼴만 Google Fonts).
- 예약할 때 개인정보 수집 동의 시각을 저장합니다. 예약일이 보관 기간(기본 180일)을 지나면 성함·연락처·메모를 자동으로 지웁니다.
- 직원의 설정 변경, 예약 수정, 내려받기, 로그인은 **활동 기록**에 남습니다.
- `public/privacy.html`의 개인정보처리방침은 초안입니다. 병원 사정에 맞게 검토하세요.

## 오픈 전에 할 일

1. **병원 정보 · 예약 규칙**에서 실제 주소, 전화, 사업자번호, 네이버 예약·카카오 채널 주소를 입력합니다.
2. **진료비**에 실제 비급여 고지 금액을 입력합니다(현재는 예시 금액).
3. **의료진**에 원장님 성함과 확인 가능한 이력을 입력합니다. 사진을 쓰려면 `public/`에 이미지를 넣고 화면을 수정합니다.
4. **진료시간 · 휴진일**에 공휴일을 미리 등록합니다(기본으로 2026-12-25, 2027-01-01만 들어 있습니다).
5. 문자 연동 주소를 설정하고, 직원 계정을 만듭니다.
6. 의료광고 심의 대상인지 확인합니다(치료 후기·전후 사진은 넣지 않았습니다).

```
  admin/       직원용 관리 화면       js/admin.js

```

### API 요약

| 경로 | 설명 |
|---|---|
| `GET /api/site` | 병원 정보, 진료시간, 휴진일, 진료비, 의료진, 공지, 진료 중 여부 |
| `GET /api/live`, `GET /api/live/stream` | 실시간 현황(진료 상태, 대기, 7일 예약 현황, 가장 빠른 시간, 오늘 진료 의료진) / 변경 신호 |
| `GET /api/days?treatment=`, `GET /api/slots?date=&treatment=` | 예약 가능한 날짜 / 시간과 남은 자리 (센터 진료 요일 반영) |
| `POST /api/reservations` | 예약 신청 |
| `POST /api/reservations/lookup`, `/cancel` | 예약번호 + 연락처로 조회·취소 |
| `POST /api/inquiries`, `/lookup`, `/cancel` | 센터 데스크 전화 상담 요청, 접수번호 + 연락처로 진행 상황 조회·취소 |
| `/api/admin/*` | 로그인, 대시보드, 예약, 설정, 콘텐츠, 계정, 기록 (로그인 필요) |

- 의료진별 예약 칸 나누기: 센터 진료 요일은 원장님 일정으로 제한하지만, 시간대 정원은 병원 전체 하나로 셉니다.
