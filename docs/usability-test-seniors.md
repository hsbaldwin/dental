# 어르신 사용성 테스트 진행표

증상 그림과 '아픈 곳 짚기'를 넣은 뒤, 60대 후반~70대 어르신이 실제로 더 쉽게 예약하는지 확인하는 진행표입니다. **그림 있는 화면과 글자만 있는 화면을 같은 과제로 비교**합니다. 한 사람당 40분 안팎, 진행자 1명과 기록자 1명이 필요합니다.

---

## 1. 준비

### 참여자 (5~6명)
| 조건 | 기준 |
|---|---|
| 나이 | 65~79세 (60대 후반을 2명 이상) |
| 휴대폰 사용 | 카카오톡만 쓰는 분 2명 이상, 인터넷 검색까지 하는 분 2명 이상 |
| 기타 | 돋보기 사용 1명 이상이면 좋음. 치과 직원 가족은 제외 |

- 사례: 소정의 사례(예: 상품권)와 음료.
- 동의: 아래 6절의 동의서를 읽어 드리고 서명을 받습니다. **녹화하지 않는 것이 기본**, 화면 녹화만 원할 때 따로 동의를 받습니다.

### 화면 준비 (로컬 테스트 서버)
```bash
npm run local:reset -- open
```
- 참여자 본인 휴대폰 또는 화면이 큰 휴대폰 1대. 서버를 켜면 출력되는 `휴대폰에서 http://…` 주소로 엽니다.
- **비교 순서**: 참여자를 두 무리로 나눠 순서를 바꿉니다(학습 효과 상쇄).
  - A 무리: 그림 있음 → 글자만
  - B 무리: 글자만 → 그림 있음
- 글자만 화면: 주소 끝에 `?picto=0` (그 탭에서 유지). 되돌리기: `?picto=1`.
- 과제마다 시작 전에 첫 화면으로 돌아갑니다. 예약이 쌓여도 상관없고, 끝나면 `npm run local:reset`.

### 준비물
- 기록지(아래 4절) 참여자 수만큼, 초시계, 큰 글씨 과제 카드(한 장에 과제 하나).
- 마스크·물·돋보기.

## 2. 진행 대본

**시작 (3분)**
> 오늘은 저희 치과 홈페이지가 쓰기 쉬운지 알아보려고 모셨어요. 어르신을 시험하는 게 아니라 **홈페이지를 시험하는 것**이에요. 막히시면 홈페이지가 잘못 만든 거니까 편하게 말씀해 주세요.
> 하시면서 **보이는 것, 드는 생각을 소리 내어 말씀**해 주시면 큰 도움이 돼요. 제가 중간에 도와드리지 않고 지켜보기만 할 거예요. 정말 모르겠으면 "그만할게요" 하셔도 됩니다.

**과제마다**
1. 과제 카드를 드리고 소리 내어 읽어 드립니다.
2. "시작하셔도 됩니다" 하고 초시계를 켭니다.
3. 도움 요청에는 "어디를 누르고 싶으세요?"로만 답합니다(정답 알려주지 않기).
4. 끝나면 "얼마나 쉬우셨어요?" 1~5 쉬움 카드를 보여 드리고 고르게 합니다.

**중단 기준**: 3분이 지나거나, 같은 곳에서 3번 이상 헤매거나, 참여자가 그만두기를 원할 때. 실패로 적고 다음 과제로.

## 3. 과제 (그림 관련 과제는 ★)

| # | 과제 카드 문구 | 성공 기준 | 시작 화면 |
|---|---|---|---|
| ★1 | "찬물을 마시면 이가 시려요. 맞는 진료를 골라 예약하는 곳까지 가 보세요." | 예약 화면에서 '이가 시려요'를 고르고 진료 항목이 충치·신경치료로 바뀜 | 첫 화면 |
| ★2 | "오른쪽 위 어금니가 시려요. 그 자리를 홈페이지에 알려 주세요." | 아픈 곳 그림에서 **윗니 오른쪽 어금니** 하나만 고름(좌우 맞음) | 과제 1 다음 |
| ★3 | "쉬운 예약으로, 잇몸에서 피가 나서 예약해 보세요. 이름은 '김테스트', 번호는 010-1234-5678." | 쉬운 예약 → 그림으로 고르기 → 잇몸 → 예약 완료 | 첫 화면 |
| ★4 | "챗봇에게 '아래 앞니가 흔들려요'라고 알리고 예약 시간을 받아 보세요." | 챗봇에서 증상 고르기 → 아픈 곳 짚기 또는 말로 설명 → 시간 제안까지 | 첫 화면 |
| 5 | "임플란트센터가 지금 접수 중인지 확인해 보세요." | 센터 데스크의 '접수 중' 또는 초록 불을 찾아 말함 | 첫 화면 |
| 6 | "방금 한 예약이 잘 됐는지 확인해 보세요." | 예약 진행 표시(확인 대기)를 찾음 | 과제 3 다음 |

- 그림 있음/글자만 비교는 ★ 과제(1~4)만 두 번 합니다. 두 번째에는 **다른 증상**으로 바꿔 주세요(예: 1번 → '씹을 때 아파요', 2번 → '왼쪽 아래 어금니').
- 과제 5·6은 한 번만(사이트 전반 확인용).

| 4 | 그림 / 글자 | | | | |

- ○ 혼자 성공, △ 진행자 힌트 한 번 뒤 성공, × 실패·중단.

**그림 관찰 체크** (보이면 표시)

- [ ] 음성 안내를 켰다 / 도움이 됐다고 말했다
- [ ] '크게 보기'를 켰다

## 5. 끝난 뒤 질문 (5분)

1. 그림이 있는 화면과 없는 화면 중 어느 쪽이 더 편하셨어요? 왜요?
2. 이 그림(증상 그림 8개를 하나씩 보여 드리며)은 무엇처럼 보이세요? → **그림 이해도**: 글자를 가리고 묻습니다. 맞힌 개수 __ / 8
3. 아픈 곳 그림에서 '오른쪽'은 어르신 오른쪽이었어요, 보는 사람 오른쪽이었어요?
4. 집에서 혼자 하신다면 할 수 있을 것 같으세요? (네 / 아마도 / 아니요)
5. 가장 불편했던 한 가지와 가장 좋았던 한 가지는요?

## 6. 동의서 (읽어 드리기)

> 오늘 테스트는 홈페이지 개선을 위한 것입니다. 성함과 연락처는 사례 전달에만 쓰고 테스트 기록에는 번호만 적습니다. 입력하시는 이름·전화번호는 연습용으로 정한 것을 쓰며, 실제 개인정보는 입력하지 않습니다. 언제든 그만두실 수 있고, 그만두셔도 사례는 그대로 드립니다. 화면 녹화는 따로 동의하실 때만 합니다.
>
> 동의합니다 □  화면 녹화에도 동의합니다 □  서명 ________

## 7. 결과 정리

| 지표 | 그림 있음 | 글자만 | 목표 |
|---|---|---|---|
| ★과제 성공률(○만) | | | 그림 있음이 80% 이상, 글자만보다 높음 |
| ★과제 평균 시간 | | | 그림 있음이 더 짧음 |
| 쉬움 평균(1~5) | | | 4 이상 |
| 그림 이해도(글자 가리고) | __ / 8 평균 | — | 6 이상. 3명 이상이 틀린 그림은 다시 그림 |
| 아픈 곳 좌우 오류 | __명 | — | 1명 이하. 2명 이상이면 '내 오른쪽' 표시 방식 수정 |

**판단 규칙**
- 그림 있음이 성공률·시간 모두 나으면 유지.
- 차이가 없으면 그림은 유지하되 **글자 크기·문구**를 먼저 손봄(그림이 해가 되지 않는 한 유지).
- 그림 있음이 더 나쁘면 그 그림만 글자 버튼으로 되돌리고 다시 시험.
- 같은 문제를 3명 이상이 겪으면 '반드시 고칠 것', 1~2명이면 '살펴볼 것'으로 분류해 개선 목록을 만듭니다.

5명만 해도 큰 문제는 대부분 드러납니다. 고친 뒤 새 참여자 3~5명으로 한 번 더 확인하면 됩니다.
